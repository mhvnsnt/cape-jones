# Cape Jones Dance Proof — 3D version (v1)

First proof of the Cape Jones production model (docs/production/CAPE-JONES-PRODUCTION-MODEL.md):
the Adult Swim limited-animation formula applied to the 3D rig.

**Deliverable video:** `~/workspace/your_files/cape-jones-dance-proof/cj-dance-proof-3d-v1.mp4`
(20.0 s, 960x540, 24 fps) + contact sheet `cj-dance-proof-3d-sheet.png` in the same folder.

## What is in the scene
- Cape Jones (the repo rig: `3d-assets/cape-jones-rig/cape_jones_mpfb_wired.blend`) dances in one
  spot in a backyard set (picket fence, lollipop trees, bushes, grass tufts, flower row) built
  from primitives in the script. Camera is LOCKED the whole video.
- The dance is ONE 48-frame loop of 8 held poses (constant/stepped interpolation, animation on
  sixes at 24 fps = the model's threes/fours family), tiled for the full 20 s. Poses are FK keys
  on the rig's BlenRig FK chains: alternating foot taps, pelvis sway, opposite arm swings,
  chest counter-twist, head tilt/nod, shrug accents. The repo's CMU mocap pack has no dance BVH
  (idle/walk/sit/gesture only), so the loop is keyed per the production model's fallback.
- Five 4-second sections, hard cuts, same dance throughout:
  1. Day (sun disc up, warm sun)
  2. LED magenta (two LED poles) — section is HORIZONTALLY FLIPPED in post, never re-animated
  3. LED cyan
  4. Night (moon, stars, fireflies) — also flipped
  5. Day again (flower row keyed orange)
  Lighting is keyframed Blender light/world/material values in the script (sun, fill, LED point
  lights, sky color, foliage colors) — the same state list the repo lighting docs describe
  (day / LED colors / night).
- Music: Tamagotchi-style chiptune loop generated by `make_chiptune.py` (square-wave lead,
  triangle bass, noise-hat ticks, 150 BPM pentatonic, deterministic seed), mixed as AAC.

## Render method (why stills)
The live rig (dense MPFB mesh + MDEF cage + CorrectiveSmooth) evaluates at ~50 s/frame on this
2-vCPU box, so the pipeline BAKES the 8 loop poses to static meshes once
(`meshes.new_from_object` on the evaluated depsgraph), deletes the live rig, and visibility-keys
the baked poses. Because the camera, set, and lighting are static inside each section, a section
is fully described by its 8 pose stills — the render step produces 40 stills (5 sections x 8
poses, ~10 s each) and ffmpeg assembles them (each still held 6 frames at 24 fps, sections 2
and 4 hflipped, concat, mux music). This is the model's "held poses, reused everything" rule
applied to the render itself.

## Rebuild
```
# 1. music (20 s)
python3 make_chiptune.py 20.0 music.wav
# 2. stills (Blender 4.0.2, headless recipe from ~/TOOLS.md + libEGL on LD_LIBRARY_PATH)
xvfb-run -a env -u PYTHONPATH blender -b cape_jones_mpfb_wired.blend \
  --python build_dance.py -- render ./stills 1 480
# 3. assemble (per section: stream_loop the 8 stills at 4 fps -> fps=24; hflip sections 2 and 4;
#    concat; mux music.wav as AAC, faststart)
```

## Honest notes on v1
- The foot taps read subtle at this framing; the loop reads as a gentle side-to-side groove
  with arm swings and shrug beats rather than a big shuffle. Pose values live at the top of
  `build_dance.py` (POSES list) — strengthening them and re-running step 2 is a ~15 min pass.
- The flower heads sit at/below the frame's bottom edge; foreground reads via the grass tufts.
- Build wall-clock was dominated by GitHub clone throttling, a libEGL fix, and finding the
  bake+stills render path on a contended 2-vCPU box — see the PR description for timings.
