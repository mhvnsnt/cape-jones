# Kaggle GPU Pipeline — Cape Jones RIFE interpolation

Repeatable setup for running RIFE frame interpolation on Kaggle's free T4 GPUs
(account `marsfmmg`, ~28 GPU-hrs/week, phone verified).

## Why

RIFE on the VM's CPU takes ~26s per frame pair at 1080x1920 (~14 min for a 3s
clip; ~3-4 hours for an 18s clip). On a T4 GPU the same work is expected to be
10-50x faster. This pipeline exists to race GPU vs CPU and to take over heavy
interpolation for future videos.

## The notebook

`~/workspace/cape-jones-build/kaggle-rife/cape_jones_rife_kaggle.ipynb`
(generated by `gen_notebook.py` — edit the generator, not the .ipynb, for changes).

7 cells:
1. **GPU check** — `nvidia-smi`, asserts Tesla T4
2. **Deps** — verifies torch+CUDA, installs opencv if missing
3. **Download** — video + model code + weights from GitHub, SHA-256 verified
4. **Extract frames** — ffmpeg, asserts 217 frames
5. **RIFE on CUDA** — exp=1 (one middle frame per pair), 216 pairs -> 433 frames
6. **Assemble** — ffmpeg 24fps MP4 + sha256 printed
7. (inline in 6) — ffprobe verification of output

## Browser-lane runbook

1. Open https://www.kaggle.com/code/new (signed in as Mars FMMG / marsfmmg).
2. Import `cape_jones_rife_kaggle.ipynb` (from `~/workspace/cape-jones-build/kaggle-rife/`).
3. Settings (right panel): **Accelerator → GPU T4 x2**, **Internet → ON**.
4. **Run All**. Record the RIFE wall time printed by cell 5.
5. Download `/kaggle/working/cape-jones-expressions-KAGGLE-24fps.mp4`
   from the right-panel file viewer.
6. Copy to `~/workspace/cape-jones-build/cape-jones-expressions-KAGGLE.mp4`.

## Race protocol (2026-10-15)

- CPU run: `flipaclip_post.sh` on the VM (RIFE stage only for the race;
  full pipeline adds de-ghost + upscale + sharpen).
- GPU run: this notebook.
- Compare: RIFE wall time (cell 5 print) vs CPU RIFE stage time.
- Output frame count must be 433 in both.

## Reuse for future videos

1. Push the new input video to `production/kaggle/rife/` on the `kaggle-rife`
   branch (or a new branch — update `BRANCH` in `gen_notebook.py`).
2. Update `VIDEO_SHA` in `gen_notebook.py` (sha256 of the new video).
3. Update the expected frame count in cell 4 (currently 217) and cell 5
   (currently 433 = 2*217 - 1).
4. Regenerate the notebook, upload, run, download.

## Failure handling

- **No GPU visible**: stop — check Settings → Accelerator. Do not run on CPU.
- **SHA-256 mismatch**: stop and report, do not run with unverified weights.
- **OOM on T4**: reduce batch — the script processes one pair at a time, so
  OOM is unlikely at 1080x1920; if it happens, extract at 960x1708 instead.
- **Quota low**: stop and report; CPU pipeline is the fallback.
