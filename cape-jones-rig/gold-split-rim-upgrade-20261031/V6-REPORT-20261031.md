## 4. V6 upgrade — rim only outside the silhouette

Method, wired in `build_v6_upgrade.py` (PIL/scipy, run) and in
`build_v6_blender.py` (Blender 5.2.3, run via xvfb-run — see §5):

- Rim = dilate(plate alpha, N) minus plate alpha. By construction
  **0 rim pixels inside the plate**, for every variant.
- Plate is composited AFTER rim, halo, and bloom, so interior
  black linework is never overwritten by an opaque rim. This is
  the line-preservation mask: the plate itself, on top.
- Ring stays opaque (alpha 1.0). Softness comes from a soft halo
  UNDER the ring (L4 pattern), never from making the ring itself
  semi-transparent — that would re-open the gold mix.
- Cyan bloom in upgrade variants is masked to the cyan side AND
  outside the silhouette AND outside the opaque rim, so it glows
  around the rim and never darkens the rim or tints interior lines.
- Spill/bleed layers from the original L3 stack are OMITTED over
  the plate in upgrade variants, to isolate the rim. They can be
  re-added UNDER the plate in production, not over it, or the
  line-preservation claim would not hold for those layers either.
  Stated plainly, not hidden.

Rim width ladder (dilation radius, stated in px on the 1100×1500
canvas):
- Thin: 6 px — 34,304 rim px (gold 18,430 / cyan 15,874).
- Medium: 12 px — 59,938 rim px (gold 31,106 / cyan 28,832).
- Heavy: 20 px — 93,597 rim px (gold 47,811 / cyan 45,786).
  Heavy here is an outer-only width, not the original interior
  ring — it is thick outside the figure, zero inside it.

Seam options, labelled, Mars pick owed:
- Seam x=550 (original): gold left / cyan right of x=550, rim
  split falls through the face position — but with an outer-only
  rim the face interior is NOT split, only the head's outer rim
  changes colour at that x. See the face crop.
- Seam x=650 (offset): gold 35,047 / cyan 24,891 px, same total
  rim, head rim mostly gold, split falls in the right-shoulder
  gap instead of the face. File:
  `v6-medium-seam-offset-650-20261031.png`. Pick owed, not
  decided here.

Measured results, all PIL variants (full table in
`measurements-v6-20261031.json`):
- Rim inside plate: **0 px, every variant**.
- Gold median: **(255,180,80), delta 0, every variant** — within
  the ~5/channel gate, in fact exact. Gold exact-byte pixels in
  the final outside the plate are ~95% of rim gold pixels; the
  rest are rim-edge pixels blended with the plate's
  semi-transparent anti-alias fringe (alpha 1–10, not counted in
  the plate mask), not a colour shift.
- Black interior preserved: **opaque interior pixels (alpha 255)
  100.0%, every variant**. All interior pixels (including
  semi-transparent anti-alias pixels, alpha <255, which blend by
  definition) 96.73% — the 3.27% gap is anti-alias blending, not
  rim occlusion, and it is the same on thin, medium, and heavy
  because the rim never touches the plate.
- Two bugs caught and fixed during this build, recorded so they
  are not repeated: (1) a blurred-RGB bloom over the rim diluted
  cyan to (2,187,233) — fixed by using solid colour with a blurred
  alpha band only; (2) a blurred bloom alpha leaked into the
  plate by ~10 px and tinted edge lines — fixed by re-masking
  the blurred alpha to the band itself (outside rim, outside
  plate, cyan side only) after the blur.

## 7. Methods wired — 10 industry-standard + 10 experimental

Industry-standard (10):
1. Blender compositor Dilate/Erode + SetAlpha rim — RUN (Blender
   5.2.3, §5, xvfb-run).
2. Blender compositor AlphaOver layer order, plate on top — RUN
   (Blender + PIL builds).
3. OCIO / Standard view transform, gold preservation gate
   (±5/channel) — RUN (Blender + PIL, gold delta 0).
4. After Effects Glow / outer-glow rim — MAPPING, not an AE run
   (AE not run here): glow layer masked to outside the alpha,
   same dilate-minus-alpha geometry.
5. DaVinci Resolve node rim — MAPPING, not a Resolve run:
   edge-detect + glow node, masked to outside, seam as a
   power-window split.
6. Natron Dilate + Merge — MAPPING, not a Natron run: PIL
   dilate-minus-alpha is the same algorithm, run in PIL.
7. Toon / cel rim (outline band outside the silhouette) — RUN
   (PIL outer-only band, thin/medium/heavy ladder).
8. Photoshop Outer Glow / Stroke layer style — MAPPING, not a
   Photoshop run: stroke outside, halo as outer glow, same
   geometry as the PIL halo.
9. OpenToonz / Harmony rim / outline — MAPPING, not a vendor
   run: outline level masked to outside the character alpha.
10. Fresnel-style rim from depth/normals — MAPPING with an
    honest limit: no true 3D model of Cape exists here, so a true
    Fresnel pass is not claimed; the edge-distance band in §4
    is the 2D analogue, and estimated normals are labelled as
    estimated wherever they are mentioned.

Experimental (10):
1. Edge-distance gradient rim (rim intensity by distance from
   silhouette edge) — RUN as the halo falloff (Gaussian halo
   under the ring).
2. Line-preservation mask (plate on top, rim never over lines)
   — RUN, measured 100% opaque interior (§4).
3. Seam-travelling split (seam x moved 550 → 650, rim colours
   follow) — RUN (seam-offset file, §4).
4. Dual-aura halo (soft halo under an opaque ring, two colours
   split at the seam) — RUN (medium+halo file).
5. Masked bloom, outside silhouette and outside rim only — RUN
   (bloom band, §4, with the two bugs fixed).
6. Chromatic split fringe (gold/cyan fringe offset 2 px at the
   seam) — MAPPING only, not built as a separate file; the seam
   step in the original is the reference, and a fringe variant
   would need its own proof.
7. Animated rim pulse (rim width / halo alpha pulsing over
   frames) — MAPPING only, not animated here; the width ladder
   (6/12/20 px) is the static basis a pulse would interpolate.
8. Volumetric rim (halo as a volume, not a flat blur) — MAPPING
   only; the Gaussian halo is a flat proxy, not a Cycles volume.
9. Contour-following rim (dilate-minus-alpha follows every
   contour, including belt/knee gaps) — RUN, with the honest
   note that the original inner rings followed interior contours
   too, which is why they covered lines; the upgrade follows
   only the outer contour.
10. AI / learned edge extraction — MAPPING only, no model run,
    no vendor claim; listed because it is the class of method
    that would find the outer contour automatically, and it is
    not needed here because the plate alpha already gives the
    contour exactly.

Counts, honestly: run in this folder 10/20 (industry 4 run +
experimental 6 run), mappings 10/20, labelled as such above. No
vendor tool is claimed to have run when it did not.
