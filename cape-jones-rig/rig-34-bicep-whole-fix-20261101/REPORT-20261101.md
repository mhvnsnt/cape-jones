# ARM 2 BICEP CROPPED — CAUSE + FIX, NO SQUARE CROP EVER
Mars 2026-11-01 01:20 CST: "Why did the bicep on arm number two get cropped? None of the things should have got square cropped off for any any reason."

## Answer, plainly
The bicep was cropped by the PIPELINE builder, not by the widget, not by Mars's placement, and not by the original piece file.

`pipeline-auto-20261101/pipeline_auto.py`, `paste_rotated()`:
`im.rotate(-rot, center=(ox*w, oy*h))` with PIL's default `expand=False`.
That rotates the piece INSIDE its own rectangle. Arm 2 upper arm is 112x256,
pivot top-centre (0.5,0), rotation 15°. Rotating about the top centre swings
the bicep bottom corners OUTSIDE the 112x256 rectangle, and PIL clips them
off squarely at the rectangle edge. That is a square crop.

Measured, same piece, same size, same rotation:
- Unrotated: 24,215 alpha px
- Pipeline in-place rotate: 18,003 alpha px — LOSS 6,212 px = 25.7%
- This fix, large-temp rotate: 24,278 alpha px — change +63 px = +0.26%
  (resampling only, no content lost)

Same bug in the pipeline builder, all pieces:
upperArmR -25.7%, forearmR -48.0%, handR -22.5%, upperArmL -7.5%,
thighR -6.5%, shinR -4.3%, handL -3.8%, forearmL -2.8%, thighL -1.3%.
Zero-rotation pieces: 0% loss, which is why only rotated pieces looked cropped.

The whole-original job did NOT fix this: its `build_whole.py` also uses
`im.rotate(..., center=...)` in place, expand=False, and its own audit only
counts alpha BEFORE rotation, never after — so it claimed WHOLE while
repeating the same 25.7% bicep loss. That job is audit only for this fix.

## Fix
Rotate on a 3x large temp canvas, then place so the widget pivot lands at
saved x+ox*w, y+oy*h. No piece is ever rotated inside its own rectangle,
so no square/rectangular crop can occur, for any piece, for any reason.
Base: APPROVED PERFECT wired version (rig-34-disassembled-wired-20261101,
Mars 2026-11-01 01:21 CST) + 01:06 saved layout. That wired builder already
used the large-temp method, which is why it looked perfect and uncropped.

Arm 2 = RIGHT arm, perfect, NOT moved otherwise: upperArmR saved 805,420,
rotation 15°, z10, pivot (0.5,0), whole piece, 112x256 display size.
