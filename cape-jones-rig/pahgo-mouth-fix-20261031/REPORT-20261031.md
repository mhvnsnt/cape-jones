## 4. Placement fix — left, down, 0.75x, wired into the builder
Old method flaw, measured: the old builder centred the transparent PATCH
box in zone [111,409,392,560], not the visible mouth. Old alpha centres:
01 AH (252.3,483.6) 279.0x133.9; 02 MBP (250.6,469.3) 281.0x20.5 (line sat
~15px high because only its top rows were alpha); 05 GK (268.1,484.2)
247.0x42.8 — a 17.5px x-jump between frames.
New method, wired in build_pahgo_fixed.py (the lip-sync builder, not a
one-off paste): Harmony-style mouth-chart substitution, one mouth layer
swapped per frame; a SINGLE target for every viseme, so the mouth does
not jump; alpha-bbox centre anchor, so the visible mouth lands on the
target; head-width proportional scale, same factor every viseme.
Old zone centre (251.5,484.5). Mars shift: LEFT -20px, DOWN +20px.
The -20/+20 is MY interpretation of Mars's "a little more" — Mars gave
direction + 0.75x, not pixel offsets, stated plainly.
NEW target, every viseme: (231.5, 504.5). Scale: old fitted x 0.75.
New sizes (alpha, after 0.75x):
  MBP-front: 178x23, scale 2.4512 (source line only 86px wide, so this is
    a 2.45x upscale — resolution limit, see §5)
  AH-front: 196x67, scale 0.7117
  GK-front: 188x30, scale 0.3968
Old GIF file on disk is actually 4 frames at 250ms, not the 24 frames

- MBP-front is FRAGMENTED, not a clean continuous closed line. In the

  model-sheet line (86px source) upscaled 2.45x merges with jaw outline

  usable resolution does NOT exist in this set. MBP-front is a front

  angle correctness for shout intensity is a real cost of going front-only.

  left/down/0.75x, front, no extra features.
- OH/OO round mouth: still 0. FV, L/SZ/TH/R/W: still 0 true shapes.
