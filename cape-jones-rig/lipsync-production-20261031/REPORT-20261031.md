### Fixes found by viewing (not hidden)

- **EE was WRONG in the old library and is fixed here.** The old EE box
  (50_RBEXPRES04) contained TWO pieces: the smile curve AND the bottom
  edge of Robin's eye mask (black + grey + white, 4809px at 288 dpi).
  Prior reports called that an innocuous "small upper mark". Zooming the
  source proves it is eye, not mouth. New EE = smile curve ONLY (1710px,
  render bbox 959,2423–1250,2532). Eye fragment dropped, documented.
- **GK corner strokes:** the teeth band is a single component, so its
  corner diagonal strokes cannot be separated by component. They are the
  source grin's own corner outlines, continuous with the teeth, and they
  read as grin corners at head scale (viewed on the fitted head). The
  chin curve BELOW the teeth (rows below white-max+8) WAS dropped. A
  trim by white x-range was tried and was a no-op (white spans the full
  width), so no teeth were cut to fake a trim — stated, not claimed.
- **MBP, clean (see §4).** **AH teeth seam:** the AH teeth row is a
  straight crop laid over a curved cavity, so at 2x mouth zoom a small
  step shows at the teeth row's corners. At head scale it reads as upper
  teeth. Labelled composite seam, not hidden.
- **OH/OO/R/W lower interior:** these are cavity-only transforms. The
  cavity's lower bay (where the tongue sat) is open at the bottom centre
  in the source shape — enclosed holes were inpainted with the nearest
  pulled pixel and columns were filled between first/last alpha per
  column, but the bay itself is exterior to the cavity outline, so it
  stays transparent and head skin shows there. At head scale it reads as
  a light lower mouth interior, not as a face fragment (the PATCH contains
  zero face pixels; the bay is transparency, not a drawn shape). Filling
  it with an invented colour would be drawing, so it was left as-is and
  disclosed here. If Mars wants a solid dark interior, that is a named
  decision, not a silent fill.
- **L tongue size:** the rotated tongue is large in the patch (it reads
  clearly as tongue-up at head scale, but it dominates the small L
  mouth). Noted as a proportion caveat; a narrower tongue is a one-line
  variant if Mars wants it smaller.
- **Skin/costume test counts on composites:** verbatim patches are
  exactly 0 skin / 0 costume pixels. Composites trip a naive skin-colour
  test on ≤0.45% of alpha pixels (worst: SZ 166/36814, TH 167/43160).
  Those pixels are resampling blends of mouth colours (tongue brown +
  teeth white blends into tan) and source antialias edge pixels, NOT
  skin/costume regions — every input pixel was verified mouth-only, and
  resizing cannot introduce a face region. Counts are in the JSON, not
  rounded to zero.

## 5. Timing system — demo/placeholder now, dialogue pass post-episode

- **System built (1/1):** a builder that takes a phoneme timeline and
  renders 24 fps frames on the clean head with the chart above, jaw proxy
  included, single target centre, smoothstep in-betweens (see phrase
  GIF). It does NOT hard-code 6f/viseme as the only timing — it follows
  whatever timeline it is given.
- **Demo proof (placeholder audio, NOT Mars dialogue):**
  `demo-dialogue-placeholder-20261031.wav` (2.0s, 24 kHz, synthesised
  syllable bursts, deliberately UNEVEN timing): PAH at 0.10s, GO at
  0.62s, SEE at 1.05s, PAH at 0.58s→1.58s. RMS per 24 fps frame, threshold
  0.08: **detected onsets [2, 14, 25, 38]** vs burst-start frames
  (floor) [2, 14, 25, 37] — 3/4 exact, 1/4 within 1 frame (the last burst
  starts 3 ms before a frame boundary, so its first full frame is the
  detected one). The GIF (`audio-demo-timing-20261031.gif`, 48f) follows
  the DETECTED onsets (onset frame +1 = consonant: MBP/GK/SZ, then vowel:
  AH/OH/EE, gaps = rest) — uneven spacing proves it is not a fixed grid.
  RMS plot + per-frame timeline JSON are saved with it.
- **What this is NOT:** this is not speech recognition, not Rhubarb
  (no Rhubarb binary on this VM, and none was downloaded in this task),
  and not Mars's dialogue. The demo bursts are tones + noise, so the
  detector is energy/onset-based, with the syllable labels coming from
  the demo's known transcript (the same way Rhubarb takes a transcript).
  It proves the TIMING SYSTEM works end-to-end; it does not prove
  phoneme recognition on real speech.
- **POST-EPISODE (0/1, per Space Ghost workflow):** once Mars fills
  dialogue for an episode, run Rhubarb (or equivalent) on the recorded
  dialogue + transcript, feed its phoneme timeline into this same
  builder, and QC the dialogue pass then. That step is owed after
