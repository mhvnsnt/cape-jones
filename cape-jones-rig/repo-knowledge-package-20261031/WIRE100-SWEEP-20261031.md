# WIRE-100 SWEEP — what was newly wired here, what is still unwired, why

Definition (standing): wiring = a real viewed Cape Jones output, or a
file verified by re-parse where the output is a file. "Documented
only" is NOT wired, and is never counted as wired below.

## Newly wired IN THIS SWEEP (3 items, with proof)
1. **Knowledge-package gate** — `check_package.py` in this folder.
   What it does: verifies all 9 package docs exist, verifies the
   snap gate + audit CSV + snap builder + gauntlet regression +
   arm-alignment QC still exist on disk, and verifies the approved
   true-final-flex file is byte-identical (md5
   03d282c8b1c56adf3fb43bb2dfe30b9a). Proof: run it —
   `python3 check_package.py` — output in `check_package_proof.json`
   (PASS at package build time; re-run before any push, do not trust
   a stale proof). This wires the package itself into the pipeline:
   a future worker cannot claim "the knowledge is intact" without
   running it.
2. **ADR + onboarding order as a pipeline step** — `ADR-20261031.md`
   + README onboarding order (README -> MEMORY-NOTE -> RULES ->
   APPROVALS -> GAPS -> METHODS -> ADR) + the rule "docs are updated
   in the SAME task that changes the thing they describe, or the task
   is not done." Wired as a documented mandatory step, not as code —
   because a doc-order rule cannot be enforced by a script without
   false failures. Proof: this package's own structure follows it.
3. **Consolidated rulebook cross-linked to gates** — every rule in
   CONSOLIDATED-RULES now carries its gate/builder/proof path
   (snap gate, knee-feet per-frame gate, gauntlet regression, arm
   alignment QC, colour tracking). Previously, several rules lived
   only as prose in separate docs. Proof: rule R1-R4 each name a
   runnable script; R7/R8 name preset JSONs that exist on disk.
