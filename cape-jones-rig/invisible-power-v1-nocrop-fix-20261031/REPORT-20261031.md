## The defect, measured before any rebuild
Source: pseudo-turn-templates-20261031, INVISIBLE-POWER, 17 frames @12fps,
body width 1.0 -> 0.02 f00-f07, outline-only hold f08-f11, return f12-f16,
outline frozen unsquashed silhouette, hard ring (180,245,255) + one soft
halo (0,200,255), visible body alpha 337,389 px.

Root cause (not the union canvas): the original build_templates.py computed
outline_of() on BASE, the figure TRIMMED to its own alpha bbox (464x1056).
MaxFilter(13)/(29) + GaussianBlur(6) halo therefore had nowhere to go
beyond the silhouette box — it was sliced flat at the bbox edge. The
finish() union canvas only added a 24 px pad around an already-cut outline,
so the final frames showed edge_touch 0 and still carried a cut glow.
This is exactly the NO-CROP-WINDOW RULE violation Mars called out: a
transparent background needs no crop window, and a trimmed-figure window
is still a crop window.

Measured cut (same outline math, same figure, padded by 80 px):
- Old outline: 105,188 alpha px, bbox (0,0,464,1056) — touches all four
  edges of its own canvas. Old outline row 0 alone: 141 alpha px, a flat
  horizontal cut across the top of the head.
- New uncropped outline: 131,199 alpha px, of which 26,011 px lie OUTSIDE
  the old BASE box: top 2,903 px, bottom 7,698 px, left 7,809 px,
  right 7,601 px.
- Halo extent in the new outline: 27 px above the head, 27 px left of the
  figure, 26 px right, 29 px below the feet.
- Old hold frames on disk alternated 104,787 / 101,915 alpha px (f08/f10 vs
  f09/f11) even though the original code appends identical OUTLINE copies;
  observed, not explained — the fixed hold frames are all identical at
  131,199 px.

## The fix — motion unchanged, canvas/outline window only
- Pad the figure by 80 px (transparent, Pillow ImageOps.expand) BEFORE the
  MaxFilter/blur outline pass, so the halo has room to form.
- Fixed frames built on the padded outline canvas (624x1216) plus a further
  40 px transparent margin on every side -> final canvas 704x1296.
  The canvas fits the figure + glow, never the reverse. No delivery crop
  is applied; any future delivery crop is a separate export step after a
  safe-area check.
- Body/outline opacity sequence, colours, and timing are the original
  logic byte-for-byte: same smoothstep, same sx sequence, same hard ring
  (180,245,255) + soft halo (0,200,255), same 12 fps.
- Grey in the GIF/MP4/contact is DISPLAY ONLY on view copies; the fixed
  masters in frames/ are transparent RGBA.
