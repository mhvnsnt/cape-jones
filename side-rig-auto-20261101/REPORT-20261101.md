## The scaling bug, plainly
Previous builders typed a different scale per piece: torso 1.3x, pelvis 1.25x,
upper arms 1.15-1.2x, legs/forearms/fists 1.0-1.1x. Those pieces were all cut
from ONE Mars-made sheet, drawn at ONE scale, so per-piece scales broke the
sheet's own proportions — torso too big vs legs, joints landing in different
places, every fix needing another hand-typed x/y.
Fix: ONE global scale for every piece, derived, not guessed.

## Research used (not rules invented here)
- Toon Boom Harmony docs, "How to Rig a Cut-out Character" (Harmony 20):
  a cut-out rig is a hierarchy from a character model, all movable parts as
  separate layers, arranged in a hierarchy — forearm a child of arm, hand a
  child of forearm, legs rigged to hips, torso -> neck -> head, arms rigged
  to torso; pegs hold pivots/transforms, drawings do not carry keyframes.
  Source: https://docs.toonboom.com/help/harmony-20/advanced/getting-started/character-building.html
- Same method in Spine (bone hierarchy, bone lengths) and Blender (armature,
  bone-parented planes) — both already in repo, both actually used here.
- Industry standard joint practice applied: pieces overlap at a joint (here
  8% of the smaller segment) so a rotation does not open a gap. That 8% is
  the only overlap parameter, applied at every joint, not per joint.

## Automated builder: build_auto.py
No per-piece x, y, or scale appears in the builder. Only structural constants:
canvas 1400x1600 (rig standard), ground 1450, head-top target 120,
start x = canvas centre 700, far-limb depth = 0.15 x scaled pelvis width,
idle forearm rotation = -90 deg (horizontal -> down, anatomical),
joint overlap = 8% (above).
Steps, all computed at runtime:
1. Anchors detected: grey joint balls by circularity filter
   (grey, fill >= 0.60-0.75, 20-110px, circular); where a piece has no ball,
   the anchor is its centreline column top/bottom (centreline = bbox centre x,
   top/bottom = first/last alpha pixel in that column — NOT the lowest point
   anywhere, which for the head is a cowl tail, and NOT bbox centre).
2. Single global scale S, solved from anchor segments:
   S = (GROUND - HEAD_TOP) / (sum(segment lengths) - sum(joint overlaps))
   Segments (native px, bottom-anchor minus top-anchor, vertical chain
   shin_boot, thigh, pelvis, torso, neck, head): see AUTO-MANIFEST.json.
   Result: S = 0.9557. Every piece is resized by S, and only S.
3. Placement, bottom-up, by anchor coincidence: shin bottom at ground,
   thigh bottom ball = shin top, pelvis bottom = thigh top ball,
   torso bottom = pelvis top, neck bottom = torso top, head bottom = neck top,
   each with the 8% overlap. Vertical-chain x is centreline-aligned
   (pelvis centreline -> torso -> neck -> head), so slanted edges do not gap.
4. Arms by shoulder ball (torso shoulder-cap circle, detected): upper arm
   top = shoulder, elbow = upper-arm bottom ball, forearm elbow = that elbow,
   fist left = forearm wrist. Idle: forearm rotated -90 deg about its elbow
   ball with the repo large-temp 3x rotate tool (fk_pivot_rotate.py, never
   in-place rotate). Bent: bent assembly placed by its shoulder ball, no flip,
   no rotation — native bent shape faces +x.
5. Cape: cape_long top at torso back edge, torso-top height, back layer;
   cape collar (side_cape_drape) centred on neck centreline at torso-top
   height, TOP layer; cape_long overlaps collar (2,343 px).
6. Far limb: same chain, x offset -depth, drawn before torso (back layer);
   near limb drawn after torso/pelvis (front layer, thigh on top of pelvis
   per Mars 10:02 instruction).
