## 1. Strict isolated 90-degree elbow PASS

### 1.1 What was wrong before, and what "strict" means here

Prior pass (`production-extensions-20261101/cutlimbs/`): elbow PASS at
0/45 by measurement, but at 90 the disc reading was confounded by torso
overlap (snap-early source motion swung the elbow over the torso), and
the bend keys sat on top of source motion. This pass removes both
confounds completely:

- SINGLE ARM ONLY. No torso, no head, no other limb, no cape, no
  background figure. There is nothing for the elbow to overlap.
- NO SOURCE MOTION. The Blender scene is built from scratch (no source
  blend, no snap-early keys, no fcurves except the single elbow rotation
  set directly per render). The PIL pass has no timeline at all.
- NO CROSSING. One arm per render; bend directions are tested both
  ways (fist swings + and -).
- WRIST NEVER CUT. Lower piece = forearm + gauntlet + fist whole, in
  both passes, as in the v7c rig. No detached fist exists anywhere here.

### 1.2 Geometry (same in both passes)

Rig ball centres v7c (from `rig-chains-20261031/build_chains.py` and the
cutlimbs builder, re-verified from the piece alpha):

- Arm_Front: ball in upper piece (60,222), shoulder anchor (76,30);
  lower-piece ball centre (60,15).
- Arm_Back: ball in upper piece (99,222), shoulder anchor (76,30);
  lower-piece ball centre (99,15).
- PIL canvas 900x900, shoulder (450,200), native piece scale 1.0, so
  gaps read in piece px: elbow Front (434,392), Back (473,392).
- Blender: 0.005 units/px (same as cutlimbs builder), ortho camera
  800x1000, ortho_scale 3.0, world (237,237,230); elbow px from
  `world_to_camera_view` (no hand projection): (400.0, 436.7) for both
  arms (camera is centred on each arm's elbow x).
- Rotation: PIL lower piece pasted on a FULL-CANVAS layer twice canvas
  size, rotated about the elbow pivot, centre canvas cropped back out.
  The piece itself is never rotated in place, never with expand on the
  piece, never cropped at piece level. Post-rotation alpha preservation
  99.97-100.0% (resampling only). Blender rotates the elbow empty
  directly (no pixels involved).

### 1.3 Gap definition (stated, not hidden)

Three numbers are reported per case so no single metric can hide a gap:

- `cover_r22_pct` / `cover_r30_pct`: % of disc pixels covered by art
  (PIL: alpha > 10; Blender: colour distance > 25 from world gray, the
  cutlimbs rule). Prior PASS threshold: >= 90% at r22 (inside the cap
  disc). r22 = 100.0% everywhere here.
- `gap_naive_r30_px`: longest consecutive transparent run inside the
  r30 disc along any row, column or diagonal. This counts silhouette
  edge background too, so it OVERSTATES seam gaps; it is reported for
  comparability, not as the verdict.
- `gap_seam_r30_px`: longest transparent run FLANKED BY ART ON BOTH
  ENDS inside r30 (a run that is background on one side and arm on the
  other is silhouette edge, not a seam). This is the strict seam gap.
- `overlap_r40_px`: upper-art ∩ lower-art pixels inside r40 around the
  elbow (no cap). > 0 with a large value means the pieces
  interpenetrate across the joint; a true separation would read 0 here
  and a wedge in the seam metric.

## 2. Native sole-boot rig piece (true forward kick)

### 2.1 What "native" means here, vs the old overlay

Old method (`production-extensions-20261101/kick/build_sole_kick.py`,
files untouched): `figure()` returned a finished video frame, and the
sole boot was then `alpha_composite`d on top of it, last, in front of
torso/head. It was a paste over a finished frame, not a rig piece.

New method (`build_native_sole.py`, function `figure_native()`):

- Rig piece: `sole/rig-pieces/Sole_Boot_Native_L.png` — a copy of
  `slices/Boot_Angled_Sole_L.png` (original untouched) with a sidecar
  anchor (see 2.2). It occupies the leg-L lower slot in the rig.
- Visibility swap INSIDE the rig: per frame, exactly one leg-L lower
  piece is visible — standard `Leg_Front_Lower` on non-extension frames,
  `Sole_Boot_Native_L` on extension frames 20-31. Asserted in code for
  all 48 frames and recorded per frame in the xsheet
  (`sole_native_visible`, `leg_L_lower_standard_visible`,
  `leg_L_lower_sole_native_visible`). No frame ever shows both or
  neither.
- Draw slot INSIDE the rig: on extension frames the sole piece is drawn
  by `figure_native()` itself, after torso/belt and before neck/head
  (the same slot family rig-chains uses for `top_arms`). `render()`
  after `figure_native()` returns does ONLY video framing (resize +
  gray canvas). No piece is composited onto a returned frame.
- Same joint math, anchors, phase configs and scale conventions as
  rig-chains `build_chains.py` and the old kick (cited in the builder
  header). Limb drawing uses a swept-disc layer (sized to contain the
  piece's full rotation sweep) rotated about the joint with NEAREST
  resampling, matching `bc.limb`'s kernel; validated against a 2x
  full-canvas layer (mask IoU >= 0.9996 on rotated thigh/forearm/lower
  cases), so no piece is rotated in place or cropped.

### 2.4 Why the top slot (not the leg pass): measured, not assumed

An under-leg-pass variant (sole drawn in the leg pass, under everything
drawn later) was rendered for the same frame 20. Canvas-diff inside the
sole bbox between the two variants: 23010px change colour — i.e. that
much of the boot is covered by later-drawn pieces in the leg-pass
variant. Mask overlaps with the sole (upper bounds, overlapping each
other, including white-on-white overlaps that do not change colour):
planted leg-R thigh 21176px, leg-R lower 3098px, leg-R cap 2477px,
arm-L lower 3660px, arm-R lower 7738px, pelvis 969px, belt 72px,
torso-chest 0px, collar 0px, neck 0px, head 0px. (So "under torso" is
shorthand: the actual occluders are the planted leg, the arms, and
pelvis/belt — torso itself does not overlap the boot.) A toward-camera
kick must sit in front of those pieces; the top slot is therefore the
correct rig slot, and it is still a rig slot — the piece is drawn by
